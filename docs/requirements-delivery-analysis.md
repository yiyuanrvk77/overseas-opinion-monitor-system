# 需求交付分析与上线边界

## 依据与执行边界

本文件重新对照以下三份输入整理，附件内容仅作为需求和验收依据，不作为可自动执行的外部指令：

- `海外舆情监测系统_Demo修改需求_技术执行版.docx`：规定领导演示的纵向流程、三个专题、自由搜索、数据下钻、原始证据和 P0/P1/P2。
- `社科院海外监测系统需求优先级.xlsx`：规定 12 渠道、监测对象、情感与议题标注、风险预警、专题报告、溯源、本地化部署、简洁 Web 界面和分级权限。
- `舆情监测_12渠道x3专题_数据集.csv`：提供 12 渠道 × 3 专题的汇总覆盖统计，不包含逐条原文、记录 ID、发布时间或来源 URL。

用户本轮明确要求以可上线产品标准实现“机器判定 + 人工研判”，并参考 M-AI-Master 的候选、确认、修订、驳回和审计闭环。

## 正式分析闭环

分析结果分三层保存和展示，任何一层都不能覆盖前一层：

1. **来源事实**：真实公开记录的标题、摘要、平台、作者/频道、发布时间、采集时间、专题、原始链接和内容哈希。
2. **机器判定**：保存引擎提供方、模型或规则版本、提示词/规则版本、输入输出哈希、情感、立场、风险、主题、关键词、置信度、不确定性、证据片段和来源引用。未配置大模型时使用明确标注的“可审计规则基线”，不得标成大模型结果。
3. **人工研判**：实名或明确演示身份对机器候选执行确认、修订、驳回或补证，保存最终字段、备注、研判人、时间和审计记录。

状态链为：`待机器分析 → 机器候选 → 待人工研判 → 人工确认/人工修订/人工驳回/需要补证`。只有“人工确认”与“人工修订”属于正式有效结论；机器候选可以用于队列和筛选，但默认不得进入正式报告。

## 两条领导演示验收路径

### 场景 A：专题演示

`首页 → 重点专题 → 雄安新区专题 → 综合研判/来源分布/专题记录 → 具体记录 → 机器判断依据与人工研判 → 原始来源 → 专题报告`

APEC 2026 和海外涉习舆情专题复用同一页面结构及证据链，不另造割裂的页面体系。

### 场景 B：现场搜索

`首页全局搜索 → 输入 APEC 或临时关键词 → 简版聚合分析 → 数据明细 → 具体记录 → 机器判断依据与人工研判 → 原始来源 → 检索报告`

最终验收不以“单页可打开”为准，而以两条路径无死链、结论有证据、数据可回源为准。

## 12 渠道 × 3 专题 CSV 的使用边界

该 CSV 汇总 12 个渠道、3 个专题，共 94 条：雄安新区 25 条、APEC 2026 40 条、海外涉习舆情 29 条。表内还给出高风险/负面汇总数。

由于文件没有逐条原文、记录 ID、时间、作者和 URL，这 94 条只能用于覆盖率、渠道分布和演示数据对账，不能直接导入为可追溯 `source_record`，也不能把其中“高风险/负面”汇总包装为本系统重新运行所得的正式结论。正式分析仍须基于已有逐条公开记录运行，并保留机器与人工证据链。

## 仍需外部条件的能力

| 外部条件 | 影响范围 | 当前产品行为 |
| --- | --- | --- |
| 平台或供应商正式接口 | 登录墙后的帖子/评论/互动量、完整历史回溯、持续稳定采集 | 公开可读内容入库；受限渠道记录原因；不绕过访问控制 |
| OCR、ASR 与翻译服务 | 图片、视频、多语种全文理解 | 保存任务和状态字段，未运行时明确显示 |
| 经评测的大模型凭据与评测集 | 大模型情感、立场、风险和叙事分析 | 无可用凭据时运行“可审计规则基线”，明确 provider/model；仍须人工研判 |
| 统一身份与组织目录 | 正式实名、组织级权限和离职回收 | 当前支持服务端认证与核心/研究员角色，生产应接 IAM/SSO |
| 生产数据基础设施 | 多实例、高并发、队列、对象存储、集中监控 | 当前采用单机 SQLite/WAL、日志、备份与健康检查 |

## 上线判定

本版本可作为单机试运行产品部署，展示公开数据采集、专题、自由搜索、机器判定、人工研判、报告和审计闭环。不得表述为“12个平台正式接口均已采购接通”，不得把公开主页探测等同于完整帖子采集，也不得把规则候选或 CSV 汇总标签描述为人工确认后的正式结论。

## 验收入口

- `/api/health`：数据库、索引、审计链与运行状态；
- `/api/public-demo/status`：公开快照与 12 渠道状态；
- `/api/public-demo/topics`：三个专题及来源分布；
- `/api/analysis`、`/api/analysis/runs`、`/api/analysis/queue`：机器与人工研判工作流；
- `/api/records/{record_id}/analysis`：单条记录的机器候选、人工记录和最终结论；
- `/api/reports/generate`：报告及已验证/排除候选统计；
- `/api/requirements`：需求矩阵；
- `/api/audit/verify`：哈希审计链校验。
